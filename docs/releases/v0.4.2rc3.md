# v0.4.2rc3: Trustworthy job states (pre-release)

The third release candidate of the `cli.py` module split. A review of rc2 found that some failures could still be reported as successes and that job state updates could race. This candidate fixes both. Routing and the Skill workflow are unchanged. npm version: `0.4.2-rc.3`.

- A nonzero AGY exit code is always a failure, even when AGY printed a partial response. That response stays in stdout and in the job result, as evidence only.
- An `ERROR` result without a response, or any provider status other than `SUCCESS` and `ERROR`, is a failure. `done_with_warnings` now means only one thing: a clean exit whose `ERROR` result still carries a response.
- Launch, cancel, worker completion and status refresh update a job under a short per-job lock. A cancel that lands while the launcher is recording the worker is no longer overwritten with `running`.
- If the cancel command itself is interrupted after the worker exits, the next `status` or `wait` resolves `canceling` into a terminal state, so `status`, `result` and `wait` agree.
- CI now runs the lifecycle tests on macOS and tests the npm package on Node 18, the declared minimum, as well as Node 20, including an install of the packed tarball.

Try it with `npx antigravity-mission-control@next install`, or `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.4.2rc3"`. Stable remains v0.4.1 and `@latest` does not move. Validation: 58 Python tests and 13 npm tests. Each fix adds a regression test that fails on rc2, and the lock race test passed 20 of 20 repeated runs.
