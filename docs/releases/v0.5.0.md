# v0.5.0: Trustworthy job states, verified on the real AGY CLI

This stable release brings the `cli.py` module split from the v0.4.2 release candidates to `@latest`, plus fixes for problems that only showed up when testing against the real AGY CLI. Routing and the Skill workflow are unchanged, and runtime routing is still the v0.3.0 Flash-first design. npm version: `0.5.0`.

**Results you can trust**

- A failed AGY run is no longer reported as a success. A nonzero exit code always fails, and any partial response is kept as evidence only. An `ERROR` result without a response fails, and so does any status other than `SUCCESS` and `ERROR`. `done_with_warnings` covers exactly two cases: a clean exit whose `ERROR` result still has a response, and a `SUCCESS` with no response.
- AGY's own print timeout ends the turn but still reports `SUCCESS` with an empty response. That now fails with exit 124.
- AGY 1.2 nests its result under `result`. Mission Control read `status` and `conversation_id` from the top level only, so a nested `ERROR` could pass and no job recorded a conversation id. As a result, `agy-mc continue` could not work with AGY 1.2. Both shapes are read now. Jobs recorded before 0.5.0 still have no conversation id and cannot be continued.
- A failed background worker is no longer relabeled `done_with_warnings` because of text on AGY's stderr.
- A `--json-schema` run whose answer is not a single JSON document is reported as `done_with_warnings`, not as a clean success. AGY does not always honour the schema.
- AGY does not enforce `plan` mode as read-only: in real runs a plan worker created a file. A `plan` run that changes a Git workspace now fails with exit 5 and lists the changed paths.
- A print-timeout error names the step AGY was stuck on (`stuck_step`), so a stalled run can be diagnosed without rerunning it.

**Workers stay on task**

- Mission Control no longer adds its workspace note to every prompt. The note is only sent when the workspace already has changes, lists only those paths, and never gives the worker the location of Mission Control's private evidence. In real runs, a worker handed that location sometimes spent its whole turn reading job files instead of doing the task, until the timeout.

**A job lifecycle without races**

- Launch, cancel, worker completion and status refresh update a job under a short per-job lock. A cancel that lands during launch is no longer overwritten with `running`.
- A job no longer hangs in `starting` if its launcher dies. If the cancel command itself is interrupted, the job no longer hangs in `canceling`: `status`, `result` and `wait` resolve it to one terminal state.

**Safer defaults**

- Broad directories are refused as workspaces: ancestors of your home directory such as `/Users`, and the system temp roots.
- `agy-mc skill uninstall` refuses a directory it did not install unless you pass `--force`. The npm `uninstall` checks every target before it changes anything.

**Verified on the real AGY CLI**

- `scripts/real_agy_check.py` is a reusable acceptance suite that runs the installed `agy` through Mission Control. It has 19 scenarios: offline guards, foreground and background runs, `continue`, cancel, a killed worker, an interrupted cancel, a wait timeout, parallel read-only jobs, `--json-schema`, the print timeout, writes in `plan` mode, the editor lock and workspace evidence. The release process now requires a clean run.
- CI runs the lifecycle tests on macOS, and tests the npm package on Node 18 (the declared minimum) and Node 20, including an install of the packed tarball.

Install or update with `npx antigravity-mission-control@latest install`, or `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.5.0"`. Validation: 64 Python tests, 13 npm tests, and 19 of 19 real-AGY scenarios against AGY 1.2.8 with `gemini-3.8-flash-high`.
