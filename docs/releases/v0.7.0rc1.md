# v0.7.0rc1: Long AGY turns no longer end with no output (pre-release)

This release candidate changes how Mission Control handles AGY turns that run long. Routing, approvals and the Skill workflow are unchanged. npm version: `0.7.0-rc.1`.

**What we measured**

- In 113 real jobs on one project (Codex and Claude Code hosts, `gemini-3.8-flash-high`), 22 failed. 17 of them were AGY print timeouts, and every one of those used the 600 s default. The workers were not stuck: each had completed dozens of steps and 30,000-70,000 output tokens when the limit hit, but AGY returns an empty response, so all of that work was lost. The other 5 were dropped model streams that AGY itself marks retryable.
- Hosts recovered by hand about 15 times, continuing the same conversation with "stop exploring and write the report now". Each of those returned in 40-220 s.

**Changes**

- Default turn limits are 1800 s for an implementer and 1200 s for other roles, instead of 600 s. `continue` follows the job's role. An explicit `--timeout-seconds` still wins.
- A turn cut short by AGY's print timeout gets one wrap-up turn in the same conversation (300 s, no tools, no edits) that asks the worker to report what it did, what is unfinished and which files it changed. A recovered run is `done_with_warnings` with `recovered after timeout_while_working`; the cut-short turn stays in the result as evidence.
- An AGY error marked `"retryable":true` (dropped stream, broken pipe) resumes the same conversation once.
- Failed results carry `failure_kind`: `timeout_while_working`, `stuck_tool` or `network_retryable`. Timeout errors add `progress` (completed steps, output tokens), so a slow worker is no longer mistaken for a hung one or for an authentication failure.

**Verified on the real AGY CLI**

- `scripts/real_agy_check.py` against AGY 1.3.2 with `gemini-3.8-flash-high`: 19 of 19. Its print-timeout scenario now cuts a foreground and a background run at 5 s and checks that both come back as `done_with_warnings` with a report.

Try it with `npx antigravity-mission-control@next install`, or `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.7.0rc1"`. Stable remains v0.6.1 and `@latest` does not move. Validation: 116 Python tests, 13 npm tests, and 19 of 19 real-AGY scenarios.
