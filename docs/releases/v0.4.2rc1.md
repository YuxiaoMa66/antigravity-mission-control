# v0.4.2rc1: Module split (pre-release)

A pre-release of an internal refactor. The 1938-line `antigravity_mission_control/cli.py` is split into modules; `cli.py` keeps `doctor`, the argument parser and `main`. Routing, signed approvals, worker execution and the Skill are unchanged, and `agy-mc --help` is byte-identical for the root command and every subcommand. npm version: `0.4.2-rc.1`.

- The modules are `common`, `routing`, `workspace`, `jobstore`, `approvals`, `usage`, `skill` and `jobs`, layered without import cycles.
- Background workers are still re-run by path, not with `-m`. A worker's working directory is your project, and `-m` would put it first on `sys.path`, so a file such as `json.py` in the project could shadow the standard library inside the worker. `cli.py` keeps a small `__package__` shim so it can still run as a script.

Try it with `npx antigravity-mission-control@next install`, or `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.4.2rc1"`. Stable remains v0.4.1 and `@latest` does not move. Validation: the Python and npm suites match the pre-split results test for test (46 and 12 tests), every top-level definition is AST-equal to the original apart from the two places that name `cli.py` for worker launch, and the installed wheel passes the runtime tests, background jobs included, with the source package hidden.
