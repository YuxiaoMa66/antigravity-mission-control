# v0.6.0: Easier job operations, hardened against malformed status

This stable release makes day-to-day job management easier and closes a class of crashes caused by malformed job status data. Routing and the Skill workflow are unchanged, and runtime routing is still the v0.3.0 Flash-first design. npm version: `0.6.0`.

**Easier job operations**

- `agy-mc status` takes `--limit N` to cap how many jobs are listed, and a repeatable `--state` to filter the list to one or more states.
- `agy-mc prune --older-than DURATION [--yes]` deletes finished jobs (`done`, `done_with_warnings`, `error`, `crashed`, `cancel_failed`, `canceled`) whose `finished_at` is older than the cutoff. It keeps unfinished jobs, jobs with a live pid, and jobs with an unknown or unparseable status or `finished_at`, never follows symlinks, and is a dry run unless `--yes` is given.
- `agy-mc wait --timeout` now also accepts `d` (days), alongside the existing `ms`, `s`, `m`, and `h` units.
- Fix: model discovery waits up to 90 seconds, and usage snapshots default to 45 seconds, because AGY 1.2.9 can take about a minute to list models.

**Hardened against malformed status**

- A job whose `job.json` or `result.json` holds a malformed `status` (not a known status string, or a `result.json` that is not an object) previously crashed `agy-mc status`, `status <id>`, `wait`, `cancel` and `prune`. A stale job with such a result, or a `result.json` with no `status`, now resolves to `crashed`. A malformed status is never written into `job.json`, and every command that reads malformed job metadata reports it as an error instead of crashing.
