# v0.7.0: Long AGY turns no longer end with no output

This stable release promotes v0.7.0rc1 and adds a read-by-range working note. Routing, approvals and the Skill workflow are unchanged. npm version: `0.7.0`.

**Why**

- In 113 real jobs on one project before this release, 22 failed. 17 were AGY print timeouts at the 600 s default while the worker was still producing output; AGY then returns an empty response and the work was lost. The other 5 were dropped model streams that AGY marks retryable.
- On v0.7.0rc1 the same project ran 47 jobs over three days with no failures and no timeouts. Implementers took 229-1638 s and reviewers and scouts up to about 1100 s, all inside the new limits. The only two warnings came from a laptop lid closed while a job ran.

**Changes since v0.6.1**

- Default turn limits are 1800 s for an implementer and 1200 s for other roles, instead of 600 s. `continue` follows the job's role; an explicit `--timeout-seconds` still wins.
- A turn cut short by AGY's print timeout gets one wrap-up turn in the same conversation (300 s, no tools, no edits) that returns the worker's report as `done_with_warnings`. If AGY times out before it reports a conversation id, there is nothing to continue and the run fails with exit 124 as before.
- An AGY error marked `"retryable":true` (dropped stream, broken pipe) resumes the same conversation once.
- Failed results carry `failure_kind` (`timeout_while_working`, `stuck_tool`, `network_retryable`); timeout errors add `progress` (completed steps, output tokens).
- New in 0.7.0: every dispatch ends with a one-line working note asking the worker to read large files by line range or search and to re-read only the changed range after an edit. On rc1, implementers still re-read the same 30-80 KB file whole 16-17 times in one turn.
- Docs: role contracts ask for jobs that fit the turn limit; host notes warn that macOS pauses AGY's and Mission Control's timers while the Mac sleeps; the collaboration protocol says parallel jobs need their own budget, because jobs launched together with the same limit time out together.

**Verified on the real AGY CLI**

- `scripts/real_agy_check.py` against AGY 1.3.4 with `gemini-3.8-flash-high`: two consecutive full runs, 19 of 19 each. An earlier run during a bad network connection passed 18 of 19: AGY timed out at 5 s before it reported a conversation id, so the print-timeout scenario had nothing to wrap up. That scenario passed on its own once the network recovered.

Install or update with `npx antigravity-mission-control@latest install`, or `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.7.0"`. Validation: 117 Python tests, 13 npm tests, and 19 of 19 real-AGY scenarios in each of two consecutive runs.
