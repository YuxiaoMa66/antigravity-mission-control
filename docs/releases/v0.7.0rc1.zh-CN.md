# v0.7.0rc1：长时间的 AGY 任务不再以无输出告终（预发布版）

这个候选版改变了 Mission Control 处理长时间 AGY 任务的方式。路由、批准与 Skill 工作流不变。npm 版本：`0.7.0-rc.1`。

**实测数据**

- 一个项目中的 113 个真实任务（Codex 与 Claude Code 两种宿主，`gemini-3.8-flash-high`）里有 22 个失败。其中 17 个是 AGY 的 print 超时，全部使用 600 秒的默认值。这些 worker 并没有卡住：触发时限时每个都已完成几十个步骤、产出 3 万到 7 万个输出 token，但 AGY 返回的是空响应，这些工作全部丢失。另外 5 个是模型流中断，AGY 自己标记为可重试。
- 宿主手动恢复了大约 15 次：在同一会话中继续，要求"停止探索，现在写报告"。每次都在 40 到 220 秒内返回。

**改动**

- 默认时限改为 implementer 1800 秒、其他角色 1200 秒，不再统一为 600 秒。`continue` 按原任务的角色取默认值。显式传入的 `--timeout-seconds` 仍然优先。
- 被 AGY print 超时截断的任务，会在同一会话中追加一轮收尾（300 秒，禁用工具，不做修改），要求 worker 报告做了什么、哪些未完成、改了哪些文件。恢复成功的任务为 `done_with_warnings`，并带有 `recovered after timeout_while_working`；被截断的那一轮保留在结果中作为证据。
- AGY 标记为 `"retryable":true` 的错误（流中断、broken pipe）会在同一会话中续跑一次。
- 失败结果带有 `failure_kind`：`timeout_while_working`、`stuck_tool` 或 `network_retryable`。超时错误还会附上 `progress`（已完成步骤数、输出 token 数），慢速 worker 不会再被误判为卡死或认证失败。

**经真实 AGY CLI 验证**

- `scripts/real_agy_check.py`：针对 AGY 1.3.2、使用 `gemini-3.8-flash-high`，19/19。其中的 print 超时场景会在 5 秒时截断一个前台任务和一个后台任务，并检查两者都以带报告的 `done_with_warnings` 返回。

试用：`npx antigravity-mission-control@next install`，或 `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.7.0rc1"`。稳定版仍是 v0.6.1，`@latest` 不变。验证：116 个 Python 测试、13 个 npm 测试，以及 19/19 的真实 AGY 场景。
