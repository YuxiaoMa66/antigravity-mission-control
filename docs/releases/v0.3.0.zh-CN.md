# v0.3.0：签名工作区范围与必跑检查

Mission Control 现在可以把编辑任务绑定到精确 Git 根目录、base commit、preflight 摘要、允许和禁止的仓库相对路径，以及冻结的必跑检查集合。该能力通过 scoped `approve` 参数按需启用，已有未配置范围的 approval 保持兼容。

派发前，scoped 运行会拒绝仓库根目录不匹配以及 approval 创建后的任何工作区漂移，并始终禁止 Git 元数据路径。provider 执行后，Mission Control 比较私有前后证据，拒绝 HEAD 变化和越界路径，检查重命名原路径与符号链接目标，并保留 provider 诊断。必跑检查从 `.agy-mc/checks.json` 解析并签入 approval，以冻结 argv、`shell=False` 和关闭标准输入的方式执行。

机械强制结果与业务验收保持分离。`scope_passed` 和 `passed` 只表示已配置约束通过。范围越界、检查失败和证据不完整统一返回退出码 5；所有结果仍保留 `acceptance: not_evaluated`，由 Codex 检查真实 diff 并作出完成认定。

普通追问和纠错从父任务签名 approval 继承精确范围，不信任可变的任务元数据；policy-bound 后续运行不能降级为旧布尔 approval。每次运行重新采集 base commit 和 preflight 摘要，同时保留两轮纠错上限。

验证覆盖路径语法、preflight 漂移、子目录工作区、dirty 与未跟踪内容、重命名、暂存变更、provider 失败、检查失败及副作用、符号链接逃逸、命令缺失、超时、取消、后台收集、签名链、发布完整性、npm 打包和隔离安装。

Python/Git：`0.3.0` / `v0.3.0`；npm 格式安装包：`0.3.0`。
