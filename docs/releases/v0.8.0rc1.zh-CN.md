# v0.8.0rc1：适配 Gemini 4 Argon 与 Claude 5.5 的路由（预发布版）

这个候选版针对 AGY 1.4.2 带来的新模型目录更新了模型路由。任务处理、批准与 Skill 工作流不变。npm 版本：`0.8.0-rc.1`。

**AGY 的变化**

- AGY 1.4.2 的 `agy models` 列出了 `gemini-4-argon-low`、`-medium`、`-high`，以及 Claude Opus 5.5 和 Sonnet 5.5，各有 `-low`、`-medium`、`-high` 三个档位。Claude Opus 4.6 和 Sonnet 4.6 已不在列表中。
- 在这份目录上，v0.7.0 完全选不到 Argon：它的非 Flash Gemini 规则只匹配 `gemini-*-pro-high`。策略 B 会给 scout、planner、reviewer 推荐 `claude-opus-5-5-low`，因为 Claude 5.5 三个档位的版本号相同，列表里排第一个的胜出。

**改动**

- 非 Flash 的 Gemini High（目前是 `gemini-4-argon-high`）在策略 A、B 中接替原来 Pro High 的位置。
- 策略 B 的 planner 和 reviewer 依次尝试非 Flash Gemini High、Claude Opus、Claude Sonnet。Argon 和 Opus 都可用时，宿主会分别询问 planner 和 reviewer 用哪一个，默认 Argon。
- 策略 B 的 scout 改为与 implementer 相同的顺序：Gemini Flash High、Medium、Low，然后是非 Flash Gemini High，再是 Claude（先 Sonnet 后 Opus）。scout 只回答小范围的只读问题，结果还要经过 planner 和 reviewer。
- Claude 的 `-low` 和 `-medium` 档不再出现在自动推荐中，与非 Flash 的非 High Gemini 的处理一致。仍可在批准名单里显式指定。
- 策略 C 不变：所有角色都使用最新的 Gemini Flash High。
- `scripts/real_agy_check.py --model` 现在用策略 B 运行 Flash High 以外的模型；之前所有运行都用策略 C，会直接拒绝这些模型。

**在真实 AGY CLI 上的验证**

- `scripts/real_agy_check.py` 在 AGY 1.4.2 上使用 `gemini-3.8-flash-high`：连续两轮完整运行，均为 19/19。使用 `--model gemini-4-argon-high` 的前台运行也通过。
- 在 AGY 1.4.2 的实时目录上运行 `agy-mc select`：策略 B 给 scout 和 implementer 选 `gemini-3.8-flash-high`，给 planner 和 reviewer 选 `gemini-4-argon-high`；加 `--avoid-family gemini` 时，planner、implementer、reviewer 选 `claude-opus-5-5-high`，scout 选 `claude-sonnet-5-5-high`。

试用：`npx antigravity-mission-control@next install`，或 `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.8.0rc1"`。稳定版仍是 v0.7.0，`@latest` 不变。验证：118 个 Python 测试、13 个 npm 测试，以及 19/19 个真实 AGY 场景。
