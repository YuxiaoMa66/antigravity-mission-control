# v0.2.0: Effective policies and workspace evidence

![Antigravity Mission Control v0.2.0](../../assets/release-v0.2.0.png)

Quota checks and existing-job operations now take the direct route. New assignments retain the default A/B/C workflow, while user-selected balanced assignments omit that presentation step.

New signed approvals bind the effective policy. Strict root approvals require `--three-rosters-presented` as a caller assertion. Use `approve --correction-of <job-id>` for corrections and `--follow-up-of <job-id>` for ordinary in-scope follow-ups; both preserve the parent assignment and policy. A third correction in a recorded chain is rejected, and ordinary follow-ups retain the count.

Runs record private before/after Git snapshots, changed-path fingerprints, diff hashes and original/dispatched prompt hashes outside the workspace. Workers receive a bounded summary of existing user changes. Background results explicitly leave acceptance to the orchestrator; provider completion alone is insufficient.

Compatibility: legacy manifests and boolean approval flags remain supported but do not gain policy-lineage enforcement. Confirmation flags are assertions, not proof of human consent. Snapshot limitations are disclosed; snapshots do not enforce ownership or replace diff review. Correction limits are per recorded chain, not a global call budget.

Validation: 29 Python tests, 8 npm installer tests, skill validation, wheel inspection and an installed-entrypoint smoke test using fake AGY. No real-worker quality benchmark was run.

Python/Git: `0.2.0` / `v0.2.0`. npm: `0.2.0`, release channel `latest`.

Visual refresh: new release cover and eight versioned command/workflow illustrations, including workspace evidence and correction lineage.
