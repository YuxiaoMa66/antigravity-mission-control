# v0.6.0：更易用的任务管理，修复了异常状态导致的崩溃

本稳定版让日常任务管理更省心，并修复了一类由异常任务状态数据引发的崩溃。路由与 Skill 工作流不变，运行时路由仍是 v0.3.0 的 Flash 优先设计。npm 版本号：`0.6.0`。

**更易用的任务管理**

- `agy-mc status` 新增 `--limit N`，限制列出的任务数量；可重复的 `--state` 用于按状态筛选任务列表。
- `agy-mc prune --older-than DURATION [--yes]` 会删除 `finished_at` 早于截止时间的已完成任务（`done`、`done_with_warnings`、`error`、`crashed`、`cancel_failed`、`canceled`）。它会保留未完成的任务、仍有存活进程的任务，以及状态或 `finished_at` 无法解析的任务；不会跟随符号链接；未加 `--yes` 时只做演练，不实际删除。
- `agy-mc wait --timeout` 现在除了 `ms`、`s`、`m`、`h` 之外，也支持 `d`（天）。
- 修复：模型发现最多等待 90 秒，额度快照默认超时为 45 秒；AGY 1.2.9 有时需要约一分钟才能列出模型。

**修复了异常状态导致的崩溃**

- 之前，`job.json` 或 `result.json` 中出现异常的 `status`（不是已知状态字符串，或 `result.json` 本身不是对象）会导致 `agy-mc status`、`status <id>`、`wait`、`cancel` 和 `prune` 崩溃。现在，带有这类结果的旧任务，或没有 `status` 字段的 `result.json`，都会被判定为 `crashed`。异常状态不会再被写入 `job.json`，读到异常任务元数据的命令都会报告为错误，而不是崩溃。
