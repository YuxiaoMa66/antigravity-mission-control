# v0.7.0：长时间的 AGY 任务不再以无输出告终

本稳定版将 v0.7.0rc1 转为正式版，并新增按范围读文件的工作提示。路由、批准与 Skill 工作流不变。npm 版本：`0.7.0`。

**原因**

- 本版本之前，一个项目中的 113 个真实任务有 22 个失败。其中 17 个是 AGY 在 600 秒默认时限下的 print 超时，当时 worker 仍在产出；AGY 随后返回空响应，工作全部丢失。另外 5 个是模型流中断，AGY 自己标记为可重试。
- 在 v0.7.0rc1 上，同一项目三天内运行了 47 个任务，没有失败，也没有超时。implementer 耗时 229 到 1638 秒，reviewer 和 scout 最长约 1100 秒，都在新时限之内。仅有的两个警告，来自任务运行期间合上了笔记本盖子。

**相对 v0.6.1 的改动**

- 默认时限改为 implementer 1800 秒、其他角色 1200 秒，不再统一为 600 秒。`continue` 按原任务的角色取默认值；显式传入的 `--timeout-seconds` 仍然优先。
- 被 AGY print 超时截断的任务，会在同一会话中追加一轮收尾（300 秒，禁用工具，不做修改），把 worker 的报告以 `done_with_warnings` 返回。如果 AGY 在给出会话 ID 之前就已超时，没有可以继续的会话，任务仍按原样以 exit 124 失败。
- AGY 标记为 `"retryable":true` 的错误（流中断、broken pipe）会在同一会话中续跑一次。
- 失败结果带有 `failure_kind`（`timeout_while_working`、`stuck_tool`、`network_retryable`）；超时错误还会附上 `progress`（已完成步骤数、输出 token 数）。
- 0.7.0 新增：每次派发的末尾会附上一行工作提示，要求 worker 按行号范围或搜索读取大文件，修改后只重读改动的范围。在 rc1 上，implementer 仍会在一轮中把同一个 30 到 80 KB 的文件整篇重读 16 到 17 次。
- 文档：角色契约要求每个任务控制在时限之内；宿主说明提醒 Mac 休眠时 AGY 与 Mission Control 的计时器都会暂停；协作协议说明并行任务需要各自的预算，因为同时发出、时限相同的任务会一起超时。

**经真实 AGY CLI 验证**

- `scripts/real_agy_check.py`：针对 AGY 1.3.4、使用 `gemini-3.8-flash-high`，连续两次完整运行，每次都是 19/19。更早一次运行时网络不佳，结果为 18/19：AGY 在 5 秒时、给出会话 ID 之前就已超时，print 超时场景没有可以收尾的会话。网络恢复后，该场景单独重跑通过。

安装或更新：`npx antigravity-mission-control@latest install`，或 `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.7.0"`。验证：117 个 Python 测试、13 个 npm 测试，以及 连续两次完整运行中各 19/19 的真实 AGY 场景。
