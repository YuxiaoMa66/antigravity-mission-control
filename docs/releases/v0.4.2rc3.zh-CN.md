# v0.4.2rc3：可信的任务状态（预发布）

`cli.py` 模块拆分的第三个候选版本。对 rc2 的审核发现，部分失败仍可能被报告为成功，任务状态更新之间也存在竞态。本版本修复了这两类问题。路由与 Skill 工作流均不变。npm 版本号：`0.4.2-rc.3`。

- AGY 非零退出码一律判为失败，即使 AGY 已输出部分响应。该响应保留在 stdout 和任务结果中，仅作为证据。
- 没有响应的 `ERROR` 结果，以及 `SUCCESS`、`ERROR` 之外的任何 provider 状态，都判为失败。`done_with_warnings` 现在只表示一种情况：正常退出，且 `ERROR` 结果仍带有响应。
- 启动、取消、worker 完成和状态刷新都在短时的单任务锁内更新任务。启动进程记录 worker 期间到达的取消，不会再被覆盖为 `running`。
- 如果 worker 已退出而取消命令本身被中断，下一次 `status` 或 `wait` 会把 `canceling` 转为终态，`status`、`result` 与 `wait` 的结论保持一致。
- AGY 1.2 把结果嵌套在 `result` 之下。此前包装器只从顶层读取 `status` 和 `conversation_id`，因此嵌套的 `ERROR` 会被当成成功，任何任务都记录不到会话 id，`agy-mc continue` 也无法使用。现在两种结构都会先展平再判定。
- AGY 自身的 print timeout 会中断这一轮，在 stderr 打印 `returning partial output`，同时仍然报告 `SUCCESS` 且响应为空。这种情况现在判为失败，退出码 124。`SUCCESS` 但完全没有响应时报告为 `done_with_warnings`。
- CI 新增 macOS 上的生命周期测试，并在声明的最低版本 Node 18 和 Node 20 上测试 npm 包，包括安装打包后的 tarball。

试用方式：`npx antigravity-mission-control@next install`，或 `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.4.2rc3"`。稳定版仍是 v0.4.1，`@latest` 不会移动。验证：60 个 Python 测试与 13 个 npm 测试，另有针对真实 AGY 1.2.8 的运行：成功、后台收集、取消、print timeout 与 `continue`。每项修复都新增了在 rc2 上会失败的回归测试，锁竞态测试重复运行 20 次全部通过。
