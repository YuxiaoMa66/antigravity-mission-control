# v0.6.1: Diagnose slow AGY starts

This stable release adds a diagnostic for a slow-start problem we measured on AGY 1.2.14. Job behavior, routing and the Skill workflow are unchanged. npm version: `0.6.1`.

**Why AGY can be slow to start**

- Headless `agy -p` does not send its first real model request until every configured MCP server has connected or timed out, 30 seconds each. One hung MCP server made a trivial call take 67 seconds instead of 5. `agy mcp disable` does not prevent the wait in headless mode.

**Diagnosing it**

- `agy-mc doctor` has a new `agy-mcp` check that lists the enabled AGY MCP servers, with a warning that each one can add up to 30 seconds to every job. It makes no model call.
- `agy-mc doctor --probe-latency` runs one minimal turn on the latest Gemini Flash High model, reports the seconds it took, and warns above 20 seconds with the enabled MCP servers as suspects. It uses a little quota. Warnings never change the doctor exit status.
- `scripts/real_agy_check.py` now allows 120 seconds for its post-lock turn, so a cold start no longer fails that scenario.

**Verified on the real AGY CLI**

- `scripts/real_agy_check.py` against AGY 1.2.14 with `gemini-3.8-flash-high`: two consecutive full runs, 19 of 19 each. Between AGY 1.2.9 and 1.2.14 the only change that touches Mission Control is that `--json-schema` now rejects a schema whose root is not an object; Mission Control passes the schema file through unchanged.

Install or update with `npx antigravity-mission-control@latest install`, or `python3 -m pip install "git+https://github.com/YuxiaoMa66/antigravity-mission-control.git@v0.6.1"`. Validation: 112 Python tests, 13 npm tests, and 19 of 19 real-AGY scenarios in each of two consecutive runs.
