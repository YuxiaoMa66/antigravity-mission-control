# v0.3.0: Signed workspace scopes and required checks

Mission Control can now bind an editing assignment to an exact Git root, base commit, preflight digest, allowed and forbidden repository-relative paths, and a frozen set of required checks. The feature is opt-in through scoped `approve` options; existing unscoped approvals remain compatible.

Before dispatch, scoped runs reject repository-root mismatches and any workspace drift since approval. Git metadata paths are always forbidden. After provider execution, Mission Control compares private before/after evidence, rejects HEAD changes and out-of-scope paths, evaluates rename origins and symlink targets, and preserves provider diagnostics. Required checks are resolved from `.agy-mc/checks.json`, signed into the approval, and executed as frozen argv with `shell=False` and standard input disabled.

Enforcement results are separate from semantic acceptance. `scope_passed` and `passed` only mean the configured mechanical constraints passed. Scope violations, failed checks, and incomplete evidence return exit code 5; every result still reports `acceptance: not_evaluated` so Codex must inspect the real diff and decide completion.

Follow-ups and corrections inherit their exact scope from the parent's signed approval rather than mutable job metadata. Policy-bound continuations cannot fall back to legacy boolean approval. They capture a fresh base commit and preflight digest while retaining the two-correction limit.

Validation covers path syntax, preflight drift, nested workspaces, dirty and untracked content, renames, staged changes, provider failures, check failures and side effects, symlink escapes, missing executables, timeouts, cancellation, background collection, signed lineage, release integrity, npm packaging and isolated installation.
